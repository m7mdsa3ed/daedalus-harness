# Changelog

All notable changes to the Daedalus harness are documented here, as a timeline:
each release is a `## [version] - date` heading (the version lives in the root
`package.json` — bump it in the same commit as the release), and under it one
`### YYYY-MM-DD` section per day the work landed, newest first. A day is the day
the files changed — read from the harness's own record of each turn's file
changes (`session_turn_changes`) — not the day it was committed, so work that
reached git in one bundle is still filed under the days it was done. New work
goes under `## [Unreleased]`, in a section for today. The server parses this
file for `GET /api/meta` (Settings › General shows it), and reads it line by
line: keep each bullet on a single line.

## [Unreleased]

### 2026-10-24

- **The Daedalus agent can speak Anthropic messages as well as OpenAI chat completions.** A profile's Daedalus link gains a protocol picker (Settings › Profiles), stored as `agents.<id>.protocol` on the profile and handed to the agent as `DAEDALUS_AGENT_PROTOCOL` (registry seed 37); `anthropic` builds the model with `@ai-sdk/anthropic` against the link's base URL (default `https://api.anthropic.com/v1`), and `prompt_cache_key` is sent on the OpenAI protocol only.
- **The Daedalus agent shows Claude's thinking on Default effort.** On the Anthropic protocol, with no effort set, it now asks an adaptive-thinking model (Opus 4.7 and newer) for `display: "summarized"`; before, those models returned their thinking blocks with the text left out.
- **An empty thinking or text delta no longer draws an empty block.** The Daedalus agent drops deltas with no text instead of forwarding them as `agent_thought_chunk`/`agent_message_chunk`.
- **The Daedalus agent accepts `none` and `max` efforts.** Both were offered by profile catalogs but silently read as "no effort"; they now reach the model and appear in the agent's effort selector.

- **The composer's placeholder stays on one line, and the touch toolbar's buttons sit closer together.** A hint drawn at `height: 0` (which is how a Tiptap placeholder avoids adding height to the empty paragraph) cannot wrap — a longer one was laid out at its full width and cut by the editor's own clipping through the middle of its second line, so "Queue a message for when the agent finishes…" read as a broken sentence over dead space in a one-line box. The hints are now short enough to fit the line they label (`"Queue a message…"`, `"Add to the held turn"`/`"Add to the paused turn"`), with the full explanation moved to the Send button's tooltip as `Hold.sendHintDetail`, where nothing is laid out for it. On a touch pointer the toolbar's `gap-2` is gone: the buttons already grow to 32px (`iconSize`), so widening the space between them only pushed the marks apart.
- **A thinking block no longer folds the group it belongs to shut while it streams.** Reasoning that arrives after the last call of a run stands outside the fold until the next call lands (`groupToolRuns`, so the thinking in progress is never hidden), and "is this the transcript's tail" was answered by `rowTailId` alone — so the group above stopped being the tail for exactly as long as the model was thinking: it collapsed the moment the block appeared and re-opened when the call after it arrived. `streamingRowIds` (`client/src/lib/transcript-rows.ts`) now answers it as the newest row plus the group under a thought standing at the tail, never through prose, and a work fold and a subagent rail ask it of their own rows because the newest item is a level down from both.
- **`@` mentions take typed references: threads, git, runs, notes, terminal output and MCP resources.** `@thread:<id>` inlines a recap of another thread, `@commit:`, `@branch:`, `@tag:` and `@git:changes|staged|last-turn|stash/N` inline the git object, `@run:`, `@kb:` and `@term:` inline a run, a knowledge entry or a `!` command's output, and `@mcp:<server>/<uri>` reads a resource a linked MCP server serves (completed by the server where it can). On send the composer posts the message to `POST /api/mentions/context` and appends one `<context>` block under a shared 30k-character budget; the bubble folds it back into a popover on each chip. Design in `docs/mention-sources.md`.
- **`@src/a.ts:40-80` mentions those lines.** The lines are numbered and inlined (a `resource_link` cannot carry a range) while the file still goes as a link, and the chip says `a.ts:40-80`.
- **The `@` menu is a registry of sources.** Tasks, MCP servers, projects, files and MCP resources moved out of `file-mentions.tsx` into `client/src/lib/mentions/sources/`, each kind has a hint row (`thread:`, `commit:`), and the server advertises the `mentionKinds` feature so an older server just gets plain text.

### 2026-10-23

- **Workflows run on a new engine whose state is a journal, so a server restart resumes a run instead of failing it.** Every run is a `wf_runs` header plus an append-only `wf_events` journal; the script replays from it at boot (`run_recovered` marks the downtime so it is not run time), completed steps are served from the journal and never re-run, unresolved approvals, timers and signal waits resume, and a step in flight follows its `onRestart` (`resume` by default, or `rerun`/`fail`). Design in `docs/workflow-engine-v2.md`.
- **`run_workflow` JSON definitions are now compiled to the same script dialect `run_script` takes, with one scheduler.** The 16-step/5-parallel limits became 64 steps and 16 wide, and steps gain `model`, `effort`, `retry` (backoff, fallback model), `tools`, `timeoutSec`, `onRestart`, `isolation`, `agentType`, `profile`/`agent`, `when` and `forEach`; the old `pump`/`readySteps` scheduler, the growing `def` and the `workflow_runs` table are gone.
- **Workflow scripts gain `map`, `vote`, `refine`, `route`, `race`, `approve`, `sleep`, `until`, `waitFor`, `sh`, `artifact` and `state`.** `approve` parks a human-only question on the parent (answered in the app, never by the agent), `sleep`/`until` are durable pausable timers, `waitFor` pairs with the new `signal_workflow` tool, and `sh` journals before it runs and refuses to silently re-run a command that may already have run.
- **Runs have real budgets and flow control.** `budgets` caps output tokens, estimated cost, agents and wall time (paused time excluded) and ends the run `budget_exceeded` with its partial result; a global scheduler adds per-run width, per-key concurrency pools and priority without head-of-line blocking.
- **Saved workflows live in the database and are shown on the project page with a Run form.** `wf_saved` is mirrored to `.claude/workflows/` so Claude Code sees the same files; the form is generated from the script's `meta.inputs` JSON Schema, and routines can run a saved workflow by name (`{kind:"workflow", ref:{name}, args}`).
- **The run card shows approvals, sleeps, signal waits and retries, plus budget meters, state, artifacts and logs.** The card keeps drawing steps from the transcript and adds the journal's gates, state and usage over REST; the four new step states (`retrying`, `awaiting_approval`, `sleeping`, `waiting_signal`) have their own pills and tints.
- **New workflow tools and routes: `list_runs`, `delete_workflow`, `signal_workflow` and the `/api/sessions/:id/workflows` family.** The MCP server moved to `server/src/workflows/mcp.ts`; `answer_approval` is deliberately not a tool, so an agent cannot answer its own human gate.
- **Backups carry the new workflow tables.** `wfRuns`, `wfEvents` and `wfSaved` replace `workflowRuns` in the bundle; runs in an old bundle are not restored.
- **Drawn answers have six new components and a prompt that says which one to reach for.** `Verdict` (the conclusion up front, with a tone), `Matrix` (a grid of yes/no/partial/n/a verdicts), `Checks` (pass/fail/warn/skip/running results with a total), `ChangeSet` (changed files with `+/-` counts and a block bar), `Findings` (review items sorted worst-first with `file:line` and a suggested fix) and `Bars` (ranked values as horizontal bars) join the Text, Process, Developer and Numbers groups, each with a note on when to use it; the prompt also now tells the model to lead with the conclusion, prefer the most specific component over a generic table, and keep one view to one point. A thread's component set picks them up on its next respawn.
- **A call's step details now open and reflow on a narrow panel.** Below 640px the Trace panel's calls draw as cards (step, model, the tools it ran, the prompt bar and its figures) grouped under their turn, and tapping one folds its details open beneath it — `DataTable`'s card list never drew an expanded row before, now opt-in per table with `expand.cards`. The details size their grids and rank lists on their own width (container queries) rather than the panel's, a long rank row puts its bar under the name instead of squeezing it, and the expanded cell wraps instead of inheriting the table's `nowrap`.

- **The Trace panel now breaks a thread's prompt down by tool and MCP server, and is redesigned around three views.** Each model call records `toolUse` (~ the billed tokens each tool's calls and results take in the history, anchored inside the `assistant`/`results` parts) and `called` (the tools the response asked to run), filled by the Daedalus agent, the gateway proxy (all three dialects, read from the reply's tool-call events), the request-body adapters and Claude's session files, and stored as `model_calls.tool_use`/`called` (schema push adds the columns). The panel switches between Overview (where the prompt went, the heaviest MCP servers and tools, the most-called tools, the biggest system-prompt sections), Tools (every built-in and MCP tool grouped under its server with its mark: times called, definition cost, calls and results in the history) and Calls (newest first, grouped by turn, each row wearing the tools it called, with the fold showing that call's split, its tools' footprint and its prefix in billed tokens rather than bare percentages).

### 2026-10-22

- **Every model call is now one trace record with its tokens divided, whichever runtime made it.** A `ModelCall` (`_daedalus/model_call`, journaled and replayed) carries the provider's exact bill (fresh input, cache read and write, output, reasoning, Claude Code's `cost_usd` where reported), timing, and an estimated split of the prompt into system prompt, built-in tools, MCP tools, your messages, the assistant's replies and tool results (`gpt-tokenizer`, scaled to the billed total so the parts always sum, drawn `~`); a part a source cannot see is `null` and named in `missing`, never guessed.
- **Which way a runtime is traced is a column on its agent row (`agents.calls_via`), with four doors and a fallback.** `acp` (the Daedalus agent counts at the AI SDK's call seam, `agent/src/trace.ts`), `otlp` (Claude Code's OpenTelemetry logs: `api_request` + raw request bodies read from the thread's own directory and deleted, `/otlp/<key>/<threadId>/v1/logs`), `proxy` (request and reply read in passing by the gateway shim), `files` (Claude, Codex and OpenCode session stores, read-only); the first that attaches is the thread's for its life (`server/src/model-calls/`), and every other thread rows from its `usage_update`, billed only. A new runtime or approach is one source file and a seed.
- **A `model_calls` ledger records every call across the install** (thread, profile, project, agent and model names snapshotted), with `GET /api/sessions/:id/calls` and `GET /api/usage/calls?groupBy=profile|model|project|agent|source`; schema push adds the table and the column.
- **The thread dock has a Trace panel and Settings › Usage a Spend tab.** Trace lists a thread's calls (turn, step, who, model, a stacked prompt bar, billed figures, time to first token, decode) with each call's system-prompt sections and tool definitions one fold below, and says which door the figures came from and what it cannot see; Spend sums the ledger by profile, model, project, agent or source.
- **Cancelling a turn on a gateway-proxied thread still stops the provider.** The shim copies a reply in passing instead of `tee()`ing it, because a tee cancels upstream only when both branches cancel.
- **A wait between steps now says what it was made of.** Hovering the clock line under a step names the parts of the wait before the next step — the model's time to first output, how long it wrote before the call opened, time held by a pause, compacting the history, backing off a failed request — and the remainder as "Other (tools settling, harness)". The Daedalus agent stamps this on each request's first tool call as `_meta.daedalus.lead` (`Meter.take`, `leadMeta` in `agent/src/turn.ts`), read by `stepLeadOf` and carried through `layoutBatches` as `gapLead`; other runtimes and older journals keep the plain tooltip.
- **The context popover now says how long the agent waited between requests, and on what.** A new "Between requests" section totals the time no model request was in flight (the loop's own calls placed on the clock, overlaps counted once, subagents left out) and splits out what the Daedalus agent could name — held by a pause or a failed turn, compacting the history, backing off a failed request — with the rest as "Tools & other" (approvals included); the per-turn Tokens popover gets the same total. It rides `_meta.daedalus.generation.waits` (`Meter.waits()` in `agent/src/metering.ts`), is summed into `TpsStats.waits` by `addTps`, and a turn with waits and no measured speed now sends a zero-token generation instead of `null`. Other runtimes send none, so the section stays hidden.
- **A thought now groups with the tool calls it explains.** With "Group the agent's steps" on, the reasoning leading a run of calls or sitting between two of them rides inside the fold instead of standing outside it; the counting line still counts calls only, and a trailing thought (the live tail) stays after the run (`groupToolRuns` in `client/src/lib/transcript-rows.ts`, `ToolRun` draws it in place).
- **A `!` command's row is collapsed by default and marked as the reader's.** The shell row folds like any Bash step (click to read its output) instead of opening on its own, stands on an emerald wash the way a parallel group stands on a primary one, and carries a "Not sent to the agent" chip beside its title, with the tooltip saying the agent neither saw the line nor its output; a folded run of `!` commands shares the wash. A new switch, Expand `!` command output (Settings › Appearance › Transcript › Shell commands, under Show `!` commands, off by default), opens every command's output again the way Expand tool output does for tool calls.
- **Show waits between steps gains an "All" preset.** Settings › Appearance › Transcript: `All` draws every wait between one step settling and the next starting, however short, beside `Off` and the `1 s+` / `3 s+` / `10 s+` floors (relabelled with the plus, since each draws only waits at least that long); the row's description now says in a sentence what the current pick draws.
- **Parallel tool calls fold into a group of their own.** With "Group the agent's steps" on, the calls one model response sent together (the runtime's step id, else the parallel call window) become one marked group inside the run — a primary wash around it and "N in parallel" on its header — and a batch of mixed kinds is grouped by kind inside it, one more level under the stretch. A new switch, Group parallel calls (on by default, under Group the agent's steps), turns it off, and off they are plain steps — the old tint behind the rows and the "N in parallel" foot under them are removed.
- **Settings › Appearance › Transcript is regrouped as eight sections with nested options, and the dock tab switches move to › Interface.** The one list of switches and the pickers drawn after it became a tree: Layout, Messages, Thinking, Tool steps, Grouping, Shell commands, Code and diffs, Motion, each answering one question, with an option that only modifies another drawn indented under it (Variant under Tool call layout, Keep the running group open under Group the agent's steps, On the first row under Sources, Group `!` commands under Show `!` commands; the sidebar's Period headings and Empty projects under Order). Second row on tabs and Marks on tabs are a Tabs group on the Interface tab, beside the sidebar's, because they are about the dock and not the transcript column. Search keeps a matching child's parent, and each tab's Reset counts and clears the keys its own groups hold (`resetLayoutOptions(keys)`), not a `sidebar` key prefix.
- **Token, speed and first-token figures are measured where they can be trusted.** The Daedalus agent meters every model call as it answers (`agent/src/metering.ts`, the SDK's `onLanguageModelCallEnd`), so a turn cancelled or failed mid-tool still reports the calls it was billed for (the figures used to vanish on `turn_ended`), and the summarizer and title calls count too. A gateway's cache write is lifted into the standard slot and subtracted from fresh input like the read, so the prompt is never counted twice. Output speed is the SDK's own per-call timing, which includes tool-argument tokens, sent as `_meta.daedalus.generation`; the server's decode clock now answers only for a turn with no tool call, where it can see every token it divides by. Time to first token starts at the model's first output instead of the first update, which was the session title and read a follow-up turn as a few milliseconds. The compaction summary sends the turn's `prompt_cache_key`.
- **The Tokens and Trajectory panels are removed, with everything that fed them.** The thread dock and inspector lose the Tokens tab and the Trajectory panel (and the `/t/:id/trace` page); the context popover keeps its plain fill and billed figures, and the Agents reading keeps each child's spend (now `lib/subagent-spend.ts`). The server drops the span store (`tracing.ts`, `bridge-trace.ts`, `trace_spans`, `GET /api/sessions/:id/spans`), the OTLP receiver (`otlp.ts`, `/otlp/*`), the prompt counters (`prompt-parts.ts`, `prompt-files.ts`, the agents' `prompt_files` and `telemetry_via` columns) and the `otel-span-fields` feature; seed 35 takes Claude Code's `OTEL_*` env keys back where they still hold the seeded template, and boot drops the dead table and columns. The Daedalus agent drops its tracer, `daedalus/trace` and the `_meta.breakdown` split. Output speed is unchanged: it is read off the thread's stream by a small `DecodeClock` instead of the turn's spans. Existing journals keep their old `_meta.breakdown` rows, which nothing reads any more.
- **The browser and everything CDP are removed; the Preview panel only shows project files and diffs.** The desktop shell no longer opens a remote-debugging port (`DAEDALUS_DEBUG_PORT`, `electron/cdp-proxy.cjs`, `createAgentPage` and the `open-preview` hand-off are gone) and no longer runs the Preview as a `<webview>` (the address bar, viewport presets, page console, element picker and docked DevTools went with it), because `chrome-devtools-mcp` could not drive it reliably. A project's Preview URL, the helper's "starts the dev server" flag and the `/api/preview` probes are removed too (the columns stay declared so a push does not drop them). A stored Preview panel that held a web address is dropped on restore; add your own browser MCP row in the library if you want an agent to drive one.
- **How much of a long thread is loaded is the reader's pick.** Settings › Appearance › Transcript gains a History group with two choices — Open with (5, 10, 20 or 50 turns, or All, which asks for no window at all so the whole log arrives) and Load earlier steps (10, 20, 50 or 100 turns per click); the window was `REPLAY_WINDOW_STEPS` in the client and the page size `EARLIER_PAGE_STEPS` in the server, and both are now read from `historyWindow`/`earlierPage` (`client/src/lib/layout-options.ts`) through `replayWindowSteps` at attach and `earlierPageSteps` at the click, with the page size travelling as `steps` on the `load_earlier` command and `GET /api/sessions/:id/earlier`, clamped server-side and absent meaning the old fixed 20 so a client that predates the setting is unchanged.

### 2026-10-21

- **Claude Code reports its own OpenTelemetry to the harness, and every model call shows its prompt by part.** A new receiver (`server/src/otlp.ts`, `POST /otlp/<key>/<threadId>/v1/{traces,logs}`, the derived key in the path as the credential) takes Claude Code's spans and `api_request_body` events (`AgentDef.telemetryVia`, seed 34, the `OTEL_*` keys in its env — editable, and only the user's values are kept): the interaction hangs under the harness's prompt span, a model call is `chat <model>` with the provider's exact input, output and cache counts, and the bridge stops deriving model and tool spans for it; the raw request body Claude Code writes to the thread's own directory is divided into system, tools, MCP and the conversation (`prompt-parts.ts`, counted without holding the event loop, a `<system-reminder>` counted as injected context rather than the person's words), written as `daedalus.prompt_parts` and deleted, and the Trajectory's span detail draws it as "Prompt by part". Our own agent gets the same from the AI SDK's `gen_ai.*` attributes on its `chat` spans. Verified end to end against a real subscription login with env only; identity attributes (email, account ids) are dropped on arrival, and a body path outside the thread's directory is neither read nor deleted. Codex and OpenCode do not export request content, so they keep the saved-file split.
- **A request's tokens are split from the runtime's own saved files, with a warning for what it does not save.** The Tokens panel now reads `AgentDef.promptFiles` (seed 32), whatever the profile: Claude Code's session JSONL gives the system prompt by section, tool schemas, MCP instructions, skills and CLAUDE.md files; Codex's rollout gives the system prompt and developer/environment messages; OpenCode's `opencode.db` gives its injected environment, MCP and skill guidance and tool listing (`server/src/prompt-files.ts`, off the event path, carried on the usage update as `_meta.daedalus.prefix`); the panel shows a "Not available" notice naming what that file cannot say (Codex and OpenCode: tool schemas; OpenCode: its own system prompt) and leaves exactly that as Agent overhead, and with nothing missing no overhead is shown.
- **The gateway shim no longer reads or tokenizes request bodies to split a prompt.** It used to buffer, parse and count every `/messages` and `/chat/completions` request on the server's single event loop (43–156 ms per model request for a 50k–400k-token prompt, measured), which froze every thread's socket for that long; the Tokens panel's split now comes from the agent's own measurement or the runtime's saved files, `gateway-token-breakdown.ts` is deleted, and journals that already hold `source: "gateway"` breakdowns still draw. OpenCode is taken back off the shim too (seed 33 restores its provider's `{baseUrl}` and drops `includeUsage`, only where the template is untouched), since the hop existed only for the split.
- **The New tab page opens a thread's panels before any message.** The page is now a draft thread inside a thread dock, so the + over the box opens Source Control, Plan, a terminal or the preview with nothing sent yet, and they come with the thread when the first message navigates to it; the greeting, the launcher strip and navigate-before-send are handed to the shared thread view through `LandingConsoleContext`, and a layout that is only the transcript is no longer stored, so throwaway drafts stop aging real layouts out.
- **An MCP call reads as the tool, with its integration on a chip.** The row's title is what happened ("Get Task") and the server that took the call is a chip beside it (`McpServerChip`, the same chip a file gets), instead of one mono `Clickup · Get Task` string; surfaces with no chip slot (the approval card, the inspector, the composer's activity line) still read the joined pair.
- **A run of tool calls is grouped by the integration it went to.** Every MCP call shares one view, so thirty calls to four servers used to fold into a single "Running 30 tools" line over six identical wrenches; the server is now part of the run's key (`runKeyOf`), so one integration's consecutive calls fold together and the line counts them per server ("Bugsnag 6 calls · Clickup 4 calls"), one mark per server. Steps are never reordered, because a call's result is often what the next call was for.

## [0.3.0] - 2026-10-21

### 2026-10-21

- **Unread threads, and the count of them.** A thread whose turn ended after you last looked wears a bold title, and the Sessions label carries how many there are; "read" is when the thread is in front of you and the window is in front of you, per device.
- **Unread automation runs.** A run ends `unread` and stays so until its page is opened; the runs list rings the unread ones and offers "Mark all read", and the Automations row in the sidebar counts them. A `skipped` run is never unread.
- **The sidebar row says what it knows on hover.** The row's hover card (`PreviewCard`, `ThreadInfoCard`) reads status, agent, profile, model, project path, when it started and last spoke and why the last turn failed; a project folder's card reads its note, path, thread count and what is running.
- **An ask can run in another project, can be continued, and keeps its parent awake.** `ask_agent` and a script's `agent()` take an optional `projectId`, `continue_agent` picks a failed, stopped or finished ask back up in the same thread, an ask has no time limit by default, and the idle sweep skips a thread whose asks, workflow runs or background tasks are still working.
- **Stop a running subagent from its row.** A child whose runtime says it can be cancelled wears a Stop while it works: an ask is cancelled through its run and the parent agent is told; a runtime's own child gets `session/cancel` on its id.
- **A thought is drawn as a step and stands between the folds.** "Thinking as a step" (default on) gives a thought its own mark and a "Thought for 12s" title with the reasoning one click behind, and grouping no longer sweeps thinking into a run of tool calls; a fold's arrow moved to the end of its line.
- **An MCP call is drawn as the exchange it is.** It wears its server's library mark instead of a kind glyph, its pane heads with the integration and tool, and the arguments stand beside a flattened answer rather than an escaped string inside a JSON tree.
- **Drag a place into the dock, or open it beside you.** A sidebar row dragged over the dock joins a strip as a tab or makes a column beside a group, and every place-shaped row offers "Open in new tab" and "Open to the side"; the New tab page's launcher is redesigned as one strip of destinations and projects.
- **A thread with background work no longer reads as done.** A Claude Code workflow that answers its prompt at "launched" keeps a status line naming the run at the foot of the transcript while it works, and a finished run is closed off by a hairline.
- **Long user messages fold.** A message taller than the fold shows its top with "Show more", and consecutive messages sent back to back show one timestamp.

### 2026-10-20

- **Routines and scheduled messages are one Automations surface.** A list, a new-automation page with templates and a schedule picker, a detail page and a run page replace the two separate pages; the list shows active, next run, running and needs-you at a glance, and the detail page reads success rate, run history and triggers.
- **Ghost-text completion in the composer.** After a pause, a fill-in-the-middle model chosen in Settings › AI suggests the rest of the line as ghost text; Tab accepts, Escape or any keystroke drops it, and a `!` line gets one-line command completions. Profiles' models now carry a kind (chat, completion, decision) and presets seed non-chat providers, so a model that cannot drive a turn stays out of the thread pickers.
- **The client is redesigned on native shadcn.** Stock type scale, surfaces, rings and radii, success/warning tokens instead of ad-hoc colours, one layout spec across pages, panels and dialogs, one spacing spec on a 4px grid, motion tokens from one set, and a connected rail through a run's steps.
- **Client and server builds are versioned and gated on features.** `server/src/compat.ts` is compiled into both halves; `/api/health` says `api` and `minClientApi`, `/api/meta` says `features`, and only a definite answer blocks the app, which offers an update path (electron-updater, the service worker, or a reload).
- **The MCP marketplace browses several sources with a detail view.** Browse reads the MCP Registry, Smithery and npm packages tagged `mcp-server`, and a result opens onto its README and, where published, its tool list.
- **Long lists and transcripts render cheaper.** The sidebar, source-control history, trace tree, file explorer, task views and import results are windowed above a threshold without absolute positioning, and the transcript re-renders only the streaming tail block and puts far settled rows to sleep at their real height (continued through Oct 21).
- **The tasks board reflows for the panel and the phone.** A board rail on wide panels, a board switcher at every width, one filters toolbar, kanban columns that snap one at a time on a narrow panel, and a task detail that lays properties beside the body (continued through Oct 21).
- **Smaller changes.** The thread status no longer counts a thread's opening as "Step n of 4", the repository indicator left the composer footer, the context-window popover leads with a dial and the bill's parts, and an MCP tool can register its own view (`tool-views/mcp-registry.tsx`).

### 2026-10-19

- **Generated answers can draw a map.** The `openui-lang` library gained a `Map` on Google Maps, loaded on a click because each render is a billed load, with a directions panel whose routing, search and places along the route are the server's `/api/geo/*` (Routes and Places APIs) and place photos; the browser gets only the referrer-restricted Maps key.
- **Generated views can be interactive, and a thread picks which component groups it is taught.** An interactive group adds buttons, fields and forms whose only action is to fill the composer, unsent; `sessions.ui_groups` (project default `projects.default_ui_groups`) replaces the on/off toggle, empty meaning off, and tables reflow to one block per row on a narrow panel.
- **Asks have a profile and model per agent per thread.** `sessions.ask_profiles`, seeded by `projects.default_ask_profiles`, holds the choice in the config menus' "Ask agents" rows; with none set the `agents` server raises a picker by MCP elicitation. An ask carries a `description` that names its row, draws as an ordinary subagent with the asked agent's mark, and its child thread folds under its parent in the sidebar.
- **A thread picks which closing suggestions the agent offers.** The follow-up picker chooses a set — follow-up prompts, project commands, quick replies, files, other agents — stored as `sessions.suggest_kinds` with a project default, replacing the single suggestions switch.

- **A started thread's model menu says the same thing as the new-thread menu.** Both derive the option set from one function that reads the model and effort off the thread's row, so what is drawn is what is sent, and a menu still probing the agent says "asking" or "failed" instead of looking empty. (continued through Sep 12, including the Default profile's empty model menu)
- **An `@` mention can name any path on the machine**, not only files under the project's cwd: `~`, absolute and relative paths that exist are attached as a `resource_link` server-side.
- **Queued and steering rows reflow on a narrow panel.** On a phone-width panel the state and time keep the caption line and the actions drop to a line of their own, so every touch target stays reachable.
- **A steer that arrives after the agent's final step is read in one more step of the same turn**; it used to be parked as context for a turn that never came.
- **The PWA install progress no longer freezes at its first tick.** `toast.update` was overwriting the toast's own id, so later updates were lost and the update offer arrived as a second card.

### 2026-09-10

- **`!` shell lines in the composer.** A `!` line is a shell command, not a prompt: the project's saved helpers are suggested, picking one fills its command into the box, and the send path runs it on the server against the project (`POST /api/sessions/:id/shell`, `server/src/shell.ts`) instead of prompting the agent. The output is journaled as a `_daedalus/shell` row, so it is part of the transcript, replayed on reload, and drawn as a Bash step open from the moment it starts.
- **Per-model off-peak pricing windows.** A model in a profile's catalog can declare the hours its provider charges less for (from, to, zone and multiplier, as with DeepSeek's off-peak discount), and the config menu shows whether the window is active, when it flips, and the effective rate (`client/src/lib/off-peak.ts`).
- **A development-server preview.** A project can name its dev server (`projects.preview_url`), and the Browser panel opens it, probing loopback for a helper marked as the one that starts it while never rewriting where the browser points.
- **Model failures say what went wrong and stop wasting retries.** A provider 400 (a bad model id, a `max_tokens` above the ceiling) is no longer retried four times before the hold, the "Retrying (n of 4)" line quotes the real cause instead of the generic "internal error" headline, and the profile form can test a model against its endpoint with the profile's own output cap, so a cap the provider rejects shows up before a turn is spent.
- **Profiles can be disabled, and later hidden, rather than deleted.** Disabling closes a profile and its usage everywhere; hiding (added Sep 12) takes it out of the pickers while its plan keeps being tracked. Both keep the row and its threads. (continued through Sep 12)
- **Stopping a steered turn no longer loses the steer.** The steered words are re-queued before the cancel and sent as the next turn once the stopped one has settled, while Escape's take-back stays limited to the newest queued row.
- **Images and audio ride through a prompt.** A steer that carries an image is still a prompt with an image in it, and the Daedalus agent hands attachments to the provider as file parts.
- **Dock popouts work in the desktop app, and more survives a reload.** A same-origin `window.open` (dockview's popout group) opens as a native child window instead of being sent to the system browser; the IDE's open editors and the sidebar's open/collapsed state are remembered across reloads. The composer and its strip also lost their borders, inactive tabs gained a tint, and the mobile header's progressive blur was restored.

### 2026-09-09

- **Agents can be installed and updated from Settings › Agents.** `POST /api/agents/:id/install` runs the row's own install line on the server. An npm-installed agent whose published `latest` differs from the running version shows a "vN available" badge and an Update button.
- **The Daedalus agent owns its retries and classifies failures before retrying.** The AI SDK's own retries are off (`maxRetries: 0`). The harness retries four times from 2s, doubling, honours a provider's `Retry-After`, and unwraps `RetryError`. A usage cap, exhausted quota or bad key is held at once rather than retried, and a Stop during a backoff no longer waits it out.

Closing the last tab lands on the new-thread console.

- **Every drawn error has a Copy button** (`ui/copy-button.tsx`), including one with only a headline, and so does a failed tool call's output.
- **A link the agent cited opens in your browser** instead of the in-app Browser panel.
- **The sidebar resizes without re-rendering React on every frame,** dragging a tab lifts it and slides the strip apart around the gap, and the web build now tints the frame around its cards, which had blended into the page without a desktop window material behind it.

### 2026-09-08

- **Escape stops the turn and takes back the message that has not landed.** `cancel {reclaim:true}` returns the newest queued row, or a steer no step has read yet, to the composer. It happens server-side before the cancel, because a cancel's settle is what would turn a held steer into a bubble.

- **The composer is one card with two rows.** Everything that adds to the message (attach, photo, mention, command, code block) sits behind "+", and everything about how it sends (queue or steer, Schedule…, the Enter preference) is behind the chevron beside Send, which a long-press or right-click also opens. A queue drain or a steer never restarts the agent, and a flush that fails re-stages and refuses to send.
- **A setting change no longer reloads the transcript.** A restart on a live thread keeps its journal and drops the `session/load` re-narration (`restart.kept`), so changing a persona or model no longer rebuilds every device's view or loses the turn boundaries that rewind and the turn rail read from.

- **A retry is announced while it waits.** The Daedalus agent sends `_daedalus/session/retry` before each backoff, saying which attempt is next and why, so a thread waiting on a flaky provider is no longer silent until the retries run out.
- **The app has one version and a changelog.** The version lives in the root `package.json`, and this file is served parsed by `GET /api/meta` and browsable in Settings › General › What's new.
- **Rules are individual entries.** Global and per-project rules each have a title and content and can be reordered, replacing the one text blob; the old blob is migrated at boot.

- **A model menu can be grouped.** A profile's models take an optional group, and the config submenu draws them under labelled headers.
