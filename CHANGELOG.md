# Changelog

All notable changes to the Daedalus harness are documented here, as a timeline:
each release is a `## [version] - date` heading (the version lives in the root
`package.json` — bump it in the same commit as the release), and under it one
`### YYYY-MM-DD` section per day the work landed, newest first. A day is the day
the files changed — read from the harness's own record of each turn's file
changes (`session_turn_changes`) — not the day it was committed, so work that
reached git in one bundle is still filed under the days it was done. New work
goes under `## [Unreleased]`, in a section for today. The server parses this
file for `GET /api/meta` (Settings › General shows it), and reads it line by
line: keep each bullet on a single line.

## [Unreleased]

### 2026-11-18

- **A model call's tokens and timing are drawn on the transcript step that made it.** A `ModelCall` now carries `toolCallIds`, the ACP ids of the calls it asked for, wherever the door can name them (the Daedalus agent's own records, a proxied reply's tool-use ids, Claude Code's OTLP `api_response_body`, which the record waits for beside the request body); the client's `callsByStep` (`lib/trace.ts`) files each record on the last of those rows, falling back to the row that was last when it landed (`ThreadCall.tailId`), so a tool step and a message row show their own call's figures. The composer's context reading, a turn's footer and a step's figure now share one popover layout (`components/reading-kit.tsx`: captioned sections, a row of tiles, one token breakdown and cache tone) instead of three, and the trace panel reads the same records (`trace.check.mjs`).
- **Throughput and time-to-first-token no longer count delivery as writing.** The decode clock drops a turn whose prose arrived in one burst after a long silence (a decode under a tenth of its lead, as the agent's metering and `tps.ts` already did) and leaves reasoning tokens the runtime billed but never streamed out of the rate; the proxy door's `ttftMs` is timed to the first frame carrying output (`OUTPUT_FRAME` in `gateway-shim.ts`), not the first byte of a keepalive or `message_start`, and a reply that was not streamed has none; the bridge's first-token clock starts after a compaction that ran before the model was asked anything; and the inspector's average says "last first token".
- **The ACP SDK is 2.7.0 (schema v1.32) in the server, agent and client, and a markdown plan now shows the file it lives in.** Schema v1.32 drops `plan_update` type `file` in favour of `markdown` with a `path`; the client reads that `path` onto the plan card's location and keeps the old `file` reader for journals written before it. The SDK's `SessionUpdate` union gains `prompt_suggestions_update`, which now takes the typed path instead of `_daedalus/session_update_ext` (`test:acp-units` counts 20 tags); `ToolCallContent` gains `session` (a child-session reference the tool readers skip, since every one filters by block type) and config categories gain `speed` (drawn like any other agent option).
- **`patch-claude-acp.mjs` is re-anchored for claude-agent-acp 0.103-0.108 and refuses anything older than 0.103.0.** The v1 agent moved to `dist/v1/acp-agent.js`, the `workflow_progress` read now lives in the module-level `taskProgressFields` of `async-tasks.js`, and the pending session state gained `subagentChecklists`, so all nine edits (workflow passthrough, background-launch replay, `SendMessage` resume) apply again; verified idempotent on 0.103.0 and 0.108.0, with `patch-claude-acp.check.mjs` and `test:acp-workflow` passing on the installed 0.108.0. The tested adapters are now claude-agent-acp 0.108.0 and codex-acp 2.7.0.

### 2026-11-17

- **A steer can be edited or taken back for five seconds after it is sent.** A steer into a running turn now waits as a queue row ("Steering in 5s", counting down) with Edit, Remove and **Steer now**, and Escape reclaims it like any queued message; when the window closes the server sends it through `queue.steer` (`SessionQueue.steerSoon`, `STEER_UNDO_MS`, `steerAt` on `QueuedMessage`). A steer into a held turn still goes at once, and a turn that ends inside the window leaves the row queued for the drain.
- **Claude Code and codex are steered for real, through `_session/steering`.** A runtime advertising `InitializeResponse._meta.steering.supported` gets a mid-turn message injected into the running turn instead of a second `session/prompt`, which claude-agent-acp and codex-acp queued as a turn behind the first; `promptRequired` or a failed request falls back to the plain prompt, and a turn whose own answer arrives while the steer is out is settled with that answer once the steer comes back (`releaseJoin`).
- **`@openuidev/react-lang` is 1.1.1** (from 1.0.1): streamed views skip re-rendering elements whose props did not change, and `@Round`/`@Abs`/`@Floor`/`@Ceil` also map over arrays, which the generated prompt now says.

### 2026-11-15

- **On Claude Code, linking the `agents` server is the choice between its engine and ours, and it closes the runtime's subagent launcher too.** The `agent` tool's workflow fields are now always advertised; linked, the bridge disallows Claude Code's `Workflow` and its `Agent` (alias `Task`) launcher and allows `mcp__agents`, so every hand-off is one tool, and unlinked the native ones stay. Seed 41 adds `builtinTools.tools.subagent: ["Agent", "Task"]` inside an existing claude-code row (a row with its own `subagent` list keeps it), and `WORKFLOW_SERVER_NAME` is removed.
- **The Daedalus agent's prompt names the harness's `agent` tool when that is how it delegates.** Under `subagents: "harness"` the deferred `mcp__agents__agent` used to be missing from the tool names the prompt was given, so it told the model it had no way to delegate; `delegationTool` now picks `task` or the harness tool, and the prompt says to load it once through tool search and when to hand off broad exploration or write a workflow for independent parts.
- **The Daedalus agent can run its tool calls from code (`repl`), behind a new switch that is off by default.** With "Run tool calls from code" on (Settings › Agents, `DAEDALUS_AGENT_CODE_MODE`), the model can write one JavaScript script that calls `read_file`, `glob`, `grep`, `edit_file`, `write_file`, `bash` and MCP tools as async functions, so a rename across files or a check of many paths takes one step and only what the script returns enters the context. Each inner call is the tool's real `execute`: it asks permission with its own kind, is validated against its own schema and draws its own transcript row (`<callId>:<n>`, replayed on load). The script runs under `unshare -rn` + `node --permission` in a bare `vm` context, with no network, filesystem, subprocess or env of its own; a host without unprivileged user namespaces is never offered the tool. Not offered in plan mode or to subagents; killed on cancel or after 10 minutes (`agent/src/tools/repl.ts`, `test:repl`).
- **A `repl` step draws its script as code, not as a raw input dump.** The row folds like Claude Code's own code rows (the calls the script made are the rows beside it); its one-line summary is the value the script returned, on one line, or `threw`/`stopped`; opened, it shows the script highlighted as JavaScript (with copy and pretty-print), then **Returned** as a JSON tree or text, **Console** for its `console.log` lines, and **Threw**/**Stopped** in the error style when it did not return (`client/src/lib/tools/code.ts` reads the agent's result text apart, `CodeRunDetail` in `tool-views/files.tsx`, `test:code`).
- **Code mode is a per-thread agent option, and a `repl` row shows which tools its script called.** The Daedalus agent now advertises a `Code mode` boolean under the thread's Agent options (beside Auto-compact), switched live with no respawn because `buildTools` reads the session's `codeMode` every turn; `DAEDALUS_AGENT_CODE_MODE` / the Settings › Agents switch is now only the default a new thread starts with, and a host that cannot run the sandbox offers neither. While a script runs, the agent counts its calls on the `repl` row's own `_meta.daedalus.repl.calls` (live, journaled at the end), and the transcript draws them as chips under the row whether it is open or not — `edit_file ×129`, `read_file ×38`, `grep ×2` (`CodeRunTools`).

### 2026-11-14




- **The server survives the database going away and says so while it reconnects.** Boot waits for Postgres with backoff instead of crashing into a pm2 restart loop; once it has failed a query on a connection error, every `/api` route answers `503 { error: "database unavailable — reconnecting" }` at once instead of waiting out the 10s connect timeout, a request arriving while down re-probes it (at most every 2s, on its own short-timeout client) and the first success marks it back up, and `/api/health` carries `database: {up, since?, error?}`.

### 2026-11-08

- **The Daedalus agent's tool search answers with the names it loaded, not their descriptions, and drops weak keyword matches.** Each description was already in the catalogue and arrives in full as the tool's definition on the next step, so echoing it paid for every one a third time on every later step; a search now returns `{tools: [{name}]}` (with a hint to select from the catalogue when nothing matched), and a keyword match scoring under half of the best one is left out instead of filling the five-result cap (`agent/src/tools/tool-search.ts`, `test:tool-search`).

### 2026-11-06

- **Picking "Default" effort on a running thread resets the agent's effort.** An empty effort used to be skipped as nothing to do, leaving the process on the effort it had while the menu said Default; the bridge now sets the selector's own `default` choice where the runtime offers one (`selectorValue` in `acp-bridge.ts`) and leaves a selector with no way to be cleared alone, and `codexDefaultEffort` names the Codex catalog's default reasoning level (`model-catalog.ts`).

### 2026-11-05

- **Workflows run five steps at once by default and the `agent` tool teaches models to split work wide.** A `steps`/`phases` definition used to default `maxParallel` to 3 while a script ran 5; the graph now takes the engine's own `defaultConcurrency`/`maxConcurrency` (`workflows/graph.ts`). The tool's manual says a phase is a barrier that waits for its slowest step, steers later steps to depend on only what they read, and adds splitting rules: split by disjoint area, keep the graph wide and shallow, size `maxParallel` to the widest layer, brief each step fully, isolate only overlapping edits, `forEach` over a schema'd list instead of a script, and end with a verify step (`workflows/manual.ts`, `agents-mcp.ts`).

### 2026-11-04

- **Generated views read in light mode.** The drawn-answer kit's hairlines, empty discs, header bands and wells were `border/70` and `muted/40` alphas tuned on dark, which on a white card came out invisible (a 0.945 line on 1.0). They are now the `--rule`, `--wash` and `--wash-strong` tokens (`index.css`), derived from the palette's own `--border`/`--muted` with a step of `--foreground` on light and the old alphas on dark, so a studio theme moves them with its palette; every component in `lib/openui/` uses them (`Plan`, `Checks`, `Rows`, `Table`, `Findings`, `KeyValue`, `Details` and the rest).
- **The built-in personas are roles a first message reveals, seeded at boot.** `server/src/persona-seeds.ts` offers Debugger, Reviewer, Architect, Planner, Explainer, Writer, Tester, Security auditor and Project manager, each with a description written as the criterion the persona classifier reads (`persona-classify.ts` labels a message with `name — description`), under the same rules as the agent and model-prompt seeds: a row is offered once per install, never rewritten, and one the user deleted stays deleted (`pnpm test:persona-seeds`). The first set — Think more, Think less, Lazy, Quick fix, General chat, Plan first, Review, Teach — is removed: they were working-style dials a first message cannot tell apart (the classifier answered with near ties and refused to pick) and each is a slash command of the same name already; a thread or project that named one moves to the nearest role (Review → Reviewer, Teach and General chat → Explainer, Plan first → Planner) or to none. App builder and every persona the user made are untouched.
- **A parallel group is drawn as a ledger, and that is the only style.** Hairlines above and below the group and between every call, no tint, with the calls on the run's rail at the same indent as a plain run's steps; the Transcript settings' group-style picker and its other five treatments (wash, card, columns, bracket, tiles) are removed, and a stored pick is ignored.
- **The installed app no longer pulls to refresh or rubber-bands as a page.** `overscroll-behavior: none` on the root and body ends scroll chaining at the last real scroller, so a drag that runs out of list on Android no longer reloads the app under a running turn and iOS no longer bounces the whole shell; tab strips keep their own x-axis `contain`.
- **Touch controls answer like native ones.** Buttons, tabs, menu rows, options, switches, labels and links take `touch-action: manipulation` (no double-tap-zoom delay), and the chrome controls — buttons, tabs, menu rows, sidebar rows — drop iOS's long-press callout sheet and text selection so a hold reaches the app's own context menu; links in a transcript keep theirs.
- **iOS launch screens.** `pnpm icons` now also renders 72 `apple-touch-startup-image` PNGs (18 iPhone/iPad classes, portrait and landscape, light and dark, the mark on the boot colour) into `client/public/splash/` plus `src/lib/splash-images.json`; `vite.config.ts` injects the `<link>` tags into `<head>` at build so `index.html` stays readable, and the images are excluded from the service worker precache because iOS fetches them once at Add to Home Screen.
- **The ACP SDK is 2.4.0 on its `/unstable` entry in all three halves.** `server/src/acp.ts` and `agent/src/acp.ts` are barrels over `@agentclientprotocol/sdk/unstable` (ACP v1 on the wire, schema v1.29), the entry whose `ClientCapabilities` types `subagents`/`plan` and whose union carries `subagent_update`; the pin moves from 1.8.0 in `server`, `agent` and `client` and `test:acp-units` asserts the runtime surface still holds.
- **The server's inbound `session/update` reroute is derived from the SDK's own schema, not a hand-kept allowlist.** The barrel reads every `sessionUpdate` tag off `schema/v1/schema.unstable.json` (`readSdkSessionUpdateTags`, 19 tags) and `rewriteInbound` re-addresses any update whose tag is outside that set to the one generic method `_daedalus/session_update_ext`; `SUBAGENT_UPDATE_METHOD`, `SUBAGENT_UPDATE_KINDS` and `isSubagentUpdate` are removed and `SessionNotification` is the SDK's type or the genuinely foreign `ExtensionSessionNotification`, no cast.

- **An unknown session id is ACP's `-32002` on both halves.** The agent throws `RequestError.sessionNotFound(id)` from `session/prompt`, `load`, `resume`, `fork`, `delete`, `archive` and `unarchive`; the server reads a `-32002` naming the id (`isSessionNotFound`) as `historyLost.reason: "not_found"` on a failed load, treats it as success on `session/close` and archive, and treats a `-32002` whose `data` names another resource or id as not this session's.

- **Rules and personas ride ACP's own `systemPrompt` where the runtime advertises it.** New spawn-instruction door `personaVia: "acp-system-prompt"` sends `systemPrompt {mode: "append", content}` on `session/new`, `load`, `resume` and `fork` only when the live `initialize` advertises `sessionCapabilities.systemPrompt`; the fallback is read off the row (a `{personaPrompt}`/`{personaFile}` template is the env door, else AIR `customInstructions`), the env half is decided on the runtime's last measured `initialize` (new `server/src/agent-capabilities.ts`), and one door is used per spawn. Seed 40 moves claude-code (`air-meta` → `acp-system-prompt`) and codex (`env` → `acp-system-prompt`, keeping `developer_instructions` as the fallback); `resolveAgentSpawn` returns a `ResolvedSpawn` with `personaInEnv` and the bridge's `airCapabilities` getter is removed.

- **Settings › Agents says whether an agent is logged in from the agent's own `auth/status` answer** (feature `agentAuthStatus`). The status probe asks ACP `auth/status` when `initialize` advertises `agentCapabilities.auth.status` and exposes it as `AgentStatus.auth` (an `AuthState` and its accounts, display only); `authenticated` is that answer, then the adapter's push, then the CLI quota probe, and the client draws it as a Logged in / Not logged in / No login needed / Login state unknown badge with the accounts in the expanded row.

### 2026-11-03
- **The composer's voice key can record the screen and attach the recording to the message.** "Screen recording" is a third mode in the voice key's fold (`hooks/use-screen-record.ts`): `getDisplayMedia` + `MediaRecorder` at 600 kbps, stopped by the key, by the browser's "Stop sharing" or just under the 10 MB attachment cap, and the `.webm` lands on the message's attachments to go out as a file; the desktop app answers `getDisplayMedia` through `setDisplayMediaRequestHandler` (the system picker on macOS 15+, else the primary screen, with loopback audio on Windows).

- **A pasted image is attached the way an uploaded one is, even when the clipboard leaves `files` empty.** The composer's paste handler now falls back to the clipboard's file `items` (an image copied from a page, some Linux and Electron clipboards), so it lands as an attachment chip through the same `files.add` path the + menu uses instead of being dropped.
- **Settings › AI › Persona classification can show the prompt the decision model is sent.** A "Show the prompt" switch draws the `{ state, questions }` body the classifier posts, built by the same `personaState`/`personaQuestion` from the current persona library through the new read-only `GET /api/decision/persona/prompt` (feature `personaPrompt`); the project and first message are placeholders.
- **A started thread's settings menu says what each change costs.** Profile, Model, Effort, MCP servers, Helper models and Session settings wear a restart glyph when a pick restarts the agent or starts the prompt cache over, with the sentence on hover and at the head of each submenu; Persona says it keeps both. The restart half is read off the agent row's `liveConfig` and the cache half off what the setting changes in the prompt (`lib/config-cost.ts`); a draft shows nothing, having no cache to lose.
- **A persona change on a started thread no longer restarts the agent or costs the prompt cache.** The system prompt keeps the persona it already carries (new `sessions.system_persona_id`, frozen at the first change) and the next prompt carries a `<persona>` block saying the change (`personaSwitchBlock`, `persona_pending`); the block reaches the agent only, never the journal, and the bubble folds it out after a reload. A rewind or fork repeats it, an agent move unfreezes it, and backups carry both columns. Needs `pnpm db:push`.
- **The `ChangeSet` and `Commits` drawn-answer components are removed.** The file-per-change list with line counts and the commit-history list are gone from the library, the `dev` group and the generated prompt; a set of changed files is drawn with `FileTree` and its added/modified/deleted markers instead.
- **The Trace panel reports each step's output speed in tok/s.** It is a step's output tokens over the time from its first chunk to its last, which is the figure benchmarks call output speed. Buffered bursts are refused (a decode under a tenth of the wait before it), so a gateway that holds the whole answer cannot read as thousands of tok/s. The Daedalus agent now sends the tokens it actually timed (`timing.decodeTokens`, without reasoning that was billed but never streamed), and the OTLP door (Claude Code) now works out the decode as `duration_ms - ttft_ms`. The `model_calls` ledger keeps `timing` in a new jsonb column, so a cold read keeps it too (`stepRate` in `tps.ts`).
- **A new Thread graph page shows every thread at work as one live flowchart.** Open it from the sidebar's Thread graph row (its count is how many threads are running, waiting on you or held) or the New tab page: each project heads its threads, an ask hangs off the thread that asked, a workflow run is a diamond over its steps (the steps not yet started drawn dashed), forks are dashed edges, and the subagents and Claude Code workflows working inside a thread nest under it, a batch of more than six folding into one count. Active shows what is running plus the threads above it, All every thread with a live agent; selecting a node opens its thread. Built client-side from the session list and the transcripts of up to 12 active threads, refreshed every 10s (`/graph`, `lib/thread/thread-graph.ts`); the agents count above the composer now names its workers through the same shared `subagentLabel`.
- **The thread's status line now shows how long the turn has been running, and the thread's total, and sits with the transcript's events instead of resting on the composer.** A working, waiting, retrying, held or sending line ticks the open turn's time from its message (`ThreadStatus.ran`, `statusFor`) plus a total that adds the thread's settled turn durations; the line no longer carries `mt-auto`, so on a short thread it follows the last event rather than sitting at the foot of the pane.

### 2026-11-02

- **A workflow card no longer reads Done or Disconnected while its steps are still running.** A turn ending used to settle every running subagent row, including steps the engine runs past that turn, which showed `disconnected` straight away. Now a child the engine spawned (its spawn carries `_meta.daedalus.runId`) is only ever settled by the engine. The card always reads the run's own view, not only once it is opened, and that view corrects a step's state where the transcript lags.
- **`agent` runs a subagent in another project when given `projectId`.** The route accepted the field, but only an ask ever honoured it, so a subagent quietly ran in the thread's own cwd.
- **`maxParallel` and `totalTimeoutSec` now apply to script and saved-workflow runs.** Previously only a `steps`/`phases` run read them. Both now travel through `/runs` and `/scripts` as flow fields.
- **`agent` refuses settings a run cannot use instead of dropping them.** A `script`/`name` run given `agent`, `profile`, `model`, `role`, `effort`, `timeoutSec` or `description` now gets an error saying why. A `steps` run now honours `role`, and a step that names one half of a pair no longer inherits the other half from the top level.
- **`agent_list` lists runs only when asked, on every runtime.** It used to always return runs where workflows are on, and never on a native-workflow runtime, so a subagent's id could not be found there.
- **An undescribed workflow is named after its first step**, not the literal `Workflow`. `phases` is now listed among the `agent` tool's shapes, and the ask picker now honours a named profile.
- **A declarative workflow's card shows every step and phase from its first spawn.** The outline sent with each spawn used to list only the steps started so far, so a 9-step pipeline read `1/2` in one unnamed column and gained a step at a time. The compiled definition now carries its whole outline in `meta.plan` (each step with its title, grouped by phase), and every spawn sends that plan with the right total and phase. A hand-written script still reports the steps it has called so far, which is all it can know.
- **A server restart no longer writes a fake cancellation into a running workflow.** On shutdown a detached run unwinds its script, and a declarative workflow then logged its in-flight step as `failed: the run was cancelled` and every dependent step as skipped. Those lines were journaled, so after the restart the card showed a cancellation that never happened while the step carried on. A detached run now journals nothing, as `shutdown` intends, and a regression test checks it.
- **A thread whose workflow is running now gets live updates even when its agent process has stopped.** A workflow step is a separate thread that reports onto its parent, so the run carries on after the parent's process is retired, for example by a server restart. Such a thread opened read-only: the client read its saved history once and never connected, so every step that started or finished afterwards stayed hidden until a reload. Its `caught_up` and session row now report a live engine run as `background` (`backgroundFields`, `backgroundActive`) whether or not a process is running, and the client attaches a socket whenever background work is live, the same as for a running turn. Attaching does not restart the agent.
- **A thread whose workflow is still running updates live when opened with no agent process.** Opening a thread the server reports as `archived` (no process, the usual case after a restart or an idle retire) put the client into a read-only "Agent stopped" phase, even while steps were still reporting onto the thread over the socket that had just attached. Events arrived but the card stayed frozen until a reload. Now `caught_up` with `background` keeps the thread live.

- **A link the agent cited opens in your browser** instead of the in-app Browser panel.
- **The sidebar resizes without re-rendering React on every frame,** dragging a tab lifts it and slides the strip apart around the gap, and the web build now tints the frame around its cards, which had blended into the page without a desktop window material behind it.

### 2026-09-08

- **Escape stops the turn and takes back the message that has not landed.** `cancel {reclaim:true}` returns the newest queued row, or a steer no step has read yet, to the composer. It happens server-side before the cancel, because a cancel's settle is what would turn a held steer into a bubble.
- **A change staged behind a stalled turn is no longer stranded.** Pressing Continue on a held turn (`resumeTurn`), or sending into one, takes the staged patch first. A pick made during the retry window used to be left behind a steer that never flushes.
- **Opening a thread opens a tab.** Clicking a thread in the sidebar no longer replaces the one you were reading; an open thread is focused rather than duplicated, and ⌘-click, "Open in new tab" and "New thread in new tab" were retired in favour of the plain click.
- **Every route can stand in a tab.** A settings page, a project page or a trace is a `page` panel rendered through the app's route table, so the dock is the main area on every route. Pages share one browsing tab that is repointed rather than piling up, and pinning a page is how you keep it. (continued through Sep 9)
- **The shell is a frame and each dock group is a card.** The header row and the tabs stand on the frame outside the card, the sidebar is transparent over the window material, and the transcript's scrollbar is hidden (the wheel and touch still scroll).
- **Windows uses Mica instead of acrylic,** and the native material follows the app's light or dark mode instead of the OS's, so a light app on a dark desktop no longer gets a dark slab behind its sidebar.
- **The queue ranks itself.** Rows are dashed more faintly the further back they wait, a steer is nearly solid with a pulsing state pill, row actions are one group that fades in on hover, and "Send all"/"Clear" appear only when there are two or more.
- **The Daedalus agent's subagents name the `task` call that launched them** (`_meta.daedalus.parentToolUseId`), so the transcript nests each child under its own row.
- **The client was split into smaller modules.** The composer, transcript items, tool views (files, web, MCP, structured, subagent), sidebar, theme studio, source control, the store and the actions moved from single large files into folders, and unused shadcn components were deleted.

## [0.1.0] - 2026-09-07

### 2026-09-07

- **The composer is one card with two rows.** Everything that adds to the message (attach, photo, mention, command, code block) sits behind "+", and everything about how it sends (queue or steer, Schedule…, the Enter preference) is behind the chevron beside Send, which a long-press or right-click also opens. (continued through Sep 8)
- **The shelf has a floor that is always there.** The project, the thread's tools and the context ring are one row (`DraftScopeRow`) on both sides of the first message. The checklist, running subagents and context readings are 24px triggers over popovers at its end, each drawing nothing when it has nothing to say, and the pile above holds only what is about the message being typed.
- **Queued messages are drawn as the messages they are.** They appear as dashed bubbles at the very end of the transcript, after any approval or question, and editing one takes it back to the composer instead of opening a second editor.
- **The landing page is the new-thread page.** `/` draws the same welcome and composer an empty thread has, with a draft minted on arrival and dropped if nothing is sent; the hero, the count band and the feature cards are gone.
- **Every setting picked on a started thread is staged, not taken at once.** A change that costs a respawn waits in `stagedConfig` and is taken by the next spawn that happens anyway, or by the next message you send (`prompt` flushes it first), with "Apply now" for anyone who would rather pay up front. A queue drain or a steer never restarts the agent, and a flush that fails re-stages and refuses to send.
- **A setting change no longer reloads the transcript.** A restart on a live thread keeps its journal and drops the `session/load` re-narration (`restart.kept`), so changing a persona or model no longer rebuilds every device's view or loses the turn boundaries that rewind and the turn rail read from.
- **Reviewing a turn is source control narrowed to its paths.** The separate changes tab, which could not stage, discard or commit, was removed.
- **Task boards have lists, multiple assignees and time tracking.** Lists (`board_lists`) group tasks into collapsible sections and rail nodes; `tasks.assignees` holds several names; estimates and tracked time show as `1h 30m`. The toolbar was rebuilt with active filter pills.
- **Storage moved to PostgreSQL.** Every query now goes through the async Drizzle `db`, and `db:export`/`db:import` scripts move data between databases.
- **A retry is announced while it waits.** The Daedalus agent sends `_daedalus/session/retry` before each backoff, saying which attempt is next and why, so a thread waiting on a flaky provider is no longer silent until the retries run out.
- **The app has one version and a changelog.** The version lives in the root `package.json`, and this file is served parsed by `GET /api/meta` and browsable in Settings › General › What's new.
- **Rules are individual entries.** Global and per-project rules each have a title and content and can be reordered, replacing the one text blob; the old blob is migrated at boot.
- **Custom themes are synced to the server,** so a theme made on one device is there on the others.
- **The Daedalus agent caps what a tool hands the model at 200k characters** (`clampToolOutput`), so a huge grep result no longer gets the whole request rejected. A `task` tool row is no longer drawn beside the subagent card that already holds the same brief and report.
- **A model menu can be grouped.** A profile's models take an optional group, and the config submenu draws them under labelled headers.

### 2026-09-06

- **The harness's own agent runtime, `daedalus`.** A turn loop on the Vercel AI SDK against any OpenAI-compatible endpoint, with its tools, MCP, subagents, compaction, saved conversations and a turn that holds on error instead of ending.
